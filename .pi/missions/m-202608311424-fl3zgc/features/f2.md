# Feature f2 — Todo domain model and JSON storage interface

## Summary

Implemented the `Todo` domain model with the required fields and status
constants, defined the `Storage` interface, and added a human-readable JSON
file-backed implementation rooted at the XDG config directory. The interface-
based design keeps the persistence layer swappable for future providers.

## Files changed

- `internal/todo/todo.go` — `Todo` struct with `ID`, `Title`, `Status`, and
  `CreatedAt` fields; `Status` type and the three status constants
  (`未开始`, `进行中`, `已完成`).
- `internal/storage/storage.go` — `Storage` interface (`Add`, `Update`,
  `Delete`, `List`), `JSONStorage` implementation, and `NewXDGStorage()` helper
  that persists to `~/.config/todo-list/todos.json`.
- `internal/todo/todo_test.go` — new tests for status constants and JSON
  marshaling/unmarshaling of the `Todo` struct.
- `internal/storage/storage_test.go` — new tests proving the interface, CRUD
  behavior, persistence across reloads, human-readable JSON output, and the XDG
  config directory path.

## Key design decisions

- `Status` is a `string`-backed type with package-level constants for the three
  contract-mandated values.
- `Todo` JSON tags use the exact keys `id`, `title`, `status`, and
  `created_at`.
- `JSONStorage` writes an indented JSON array (`json.MarshalIndent`) so the
  file is human-readable.
- `Add` normalizes empty fields: missing IDs become sequential `todo-N`
  strings, empty status becomes `未开始`, and zero `CreatedAt` becomes the
  current UTC time.
- `NewXDGStorage()` uses `github.com/adrg/xdg` to resolve the config home and
  creates `todo-list/todos.json` there.
- The `Storage` interface lets callers depend on an abstraction rather than
  the concrete JSON store.

## Out of scope / residual notes

- No TUI rendering, tab switching, key bindings, or Bubble Tea model wiring is
  implemented in this feature; that belongs to the TUI features (f4–f6,
  f8–f11).
- Filtering todos by status for display is not implemented here; it will be
  handled by the TUI layer consuming `Storage.List()`.
- No UUID dependency was added; IDs are sequential `todo-N` strings derived
  from the existing store contents.
- The real XDG config directory is not touched during tests; tests override
  `XDG_CONFIG_HOME` to a temporary directory and call `xdg.Reload()`.
